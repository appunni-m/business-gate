## Implemented changes

- **Exact-number focus:** a native regression reproduced keyboard focus loss after committed row refresh. Interactive rows now participate correctly in native list focus. Same-number headers and their native controls remain mounted across updates; listeners bind current account values. Bounded keyboard restoration uses data identity, receiver namespace, full phone and role, and cancels on user movement or lifecycle/context changes. Tab/Shift-Tab visit the native controls within the current row before the platform list handles row boundaries; a reproduced native vertical-navigation shortcut had skipped the summary/switch pair. Space and Enter each commit one exact-number change. A 2 dp blue/light outline makes keyboard focus visible. Accessibility focus remains controlled by Android and the screen reader.
- **Accessible row presentation:** one summary groups name, full number and state; decorative/redundant child labels are excluded. Native switches expose their current checked state. Search accepts 128 Unicode code points without splitting supplementary characters. Failed saves display the durable switch choice and distinguish the unsaved request with explicit Retry save.
- **Supporting flows:** the menu has four entries; connection and receiver management are under Compatibility & help. Unblock now requires exact-number confirmation. Positive dialog callbacks expire after relevant data/receiver/revision/authority or Activity changes. Stopped Activities dismiss dialogs, and unsent number forms restore only in the same data/receiver context. A reproduced stop-before-save lifecycle ordering bug is fixed by capturing the draft before dismissal. No confirmation or draft is automatically submitted.
- **Back behavior:** a real API 36 keyboard/IME test found that the registered Back callback was not enabled in the manifest. The Activity now explicitly enables the API 33+ callback, with the existing API 29–32 fallback. Back closes the IME, then collapses details/cancels the form, then exits while retaining choices.
- **Announcements and dismissed controls:** ordinary status refreshes are no longer a live region. A completed foreground choice emits one explicit accessibility event; a save finishing after Home stays silent. Custom controls require a shown, focused window. Settings switches retain their data/receiver scope, and an asynchronous effort result cannot reopen canceled Settings. These checks observe owned events, not spoken audio quality.
- **Actual permission lifecycle:** the debug harness enables, revokes and reconnects its own screen service through Android. It verifies epoch invalidation, retained choices, cleared one-shot grants and no restored target/session with an empty registry, then restores the prior emulator settings. Reminder cases exercise actual notification denial, grant, silent/private delivery, blocked channel, 30-day/future-clock boundaries and consent withdrawal, using only synthetic debug data.
- **Delivery:** external actions and actionlint are pinned. Verification retains an environment and per-case evidence manifest, failed/unrun cells, owned rendering hashes, minimum-API UI evidence and signed-upgrade evidence. Releases carry the hash-bound manifest. Anonymous post-publication checks verify public bytes, metadata, certificate, capabilities and versioned/rolling Git references, with finite retries. Publication failure tests cover draft resumption, each later mutation boundary, stale releases, pagination and immutable reruns.

## Measured short-screen design adjustment

At 720×1280 and 450 dpi, three-button navigation plus 200% text left a 131 px list viewport; one 48 dp target needs 135 px. Short portrait windows below 600 dp therefore move title/status into the same scrolling list. The action controls and search retain separate fixed rows in narrow portrait. Wide landscape retains its single fixed search/action row. This avoids shrinking text or squeezing search beside controls in a narrow width. The regression retains the original 48 dp viewport requirement. At larger text or short height, full dialog headings and body content share one native scroll area; headings never ellipsize. Native dialog actions stack when their measured text and padding exceed the button panel width. Android may also supply a scrollable button panel; the harness requires each entire button to be reachable, and still rejects clipping in fixed controls. Dialog width uses the activity's visible frame, excluding the side navigation bar that otherwise clipped landscape fields. Scrollable supporting content uses the explicit surface and blue focus outline so platform focus highlighting does not obscure its text contrast.
