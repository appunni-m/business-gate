# Project rules

- Use only Business Gate branding. Never include the external messenger's product name, wordmark, logo, recognizable visual identity, or literal package identifier in source, resources, documentation, fixtures, filenames, artifacts, or commit messages. The automated brand gate is mandatory. Do not disguise restricted names with encoding or string concatenation to create an integration.
- Use an original blue gate identity and Android system components.
- Java 17 and Android framework APIs only; no third-party runtime libraries, network access, analytics, account login, or subscription.
- An empty compatibility registry must disable connected-app actions. Never invent measured selectors, signing identities, receiving-account bindings, physical test evidence, or successful blocking results.
- Independent sender-side blocked-delivery trials are outside the accepted scope. Verify fresh exact-profile native Block/Unblock postconditions; the connected app handles subsequent message blocking. Do not mark omitted delivery tests as passed or require a second sender account for this purpose.
- Preserve exact-number choices. Personal, uncertain, group, and unsupported contexts cannot be automatically blocked. A sales hint never grants action authority.
- The owner authorizes automatic notification dismissal by exact displayed-name rules after explicit feature consent. Bundled and locally learned names remain heuristic rules, never proof of sender identity. Whitelist and exact-number choices must be preserved; ambiguous exceptions remain visible. No background activity launches accompany dismissal.
- Every native Block/Unblock mutation requires fresh identity, explicit authority, current revisions, qualified structure, a finite session, and visible Stop. No coordinates, gestures, message-tree traversal, or background activity takeover.
- Before pushing, run pure tests, schema/brand gates, Android lint, debug/release builds, and the available device harness. Document unrun physical qualification separately.
